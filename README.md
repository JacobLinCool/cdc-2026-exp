# 台灣暗棋 AI

以 Rust 撰寫的台灣暗棋（4×8、32 子蓋牌）引擎，編譯成 WebAssembly 後在瀏覽器裡執行，附一個可以直接跟它對弈的網頁。

- **搜尋**：Expectiminimax + alpha-beta，翻子視為機會節點（Star1 剪枝）
- **評估**：依「天敵數」變動的動態子力，參數全部由自我對弈（SPSA）學出
- **兩種版本**：Light 使用原版評估；Lightning 使用 499 個可訓練參數的結構化學習評估，兩者共用搜尋與殘局庫
- **殘局**：≤ 4 子時即時逆推出完美解，並考慮 60 步無進展判和
- **Mixture of Experts**：多位專家依局面加權決策，每局走法都不一樣
- **回放與分享**：一局棋由發牌種子與著法序列完整決定，編成 `?r=` 連結（150 步約 260 字元），打開即可逐步回放、拖動進度、從任一步接手對弈
- **WebMCP**：頁面以 `document.modelContext.registerTool` 註冊工具（讀取盤面、下棋、請引擎建議、開新局、悔棋、分享與回放），瀏覽器裡的 AI 助理可以直接讀取與對弈；說明見 `web/public/llms.txt`
- **音效**：全部以 Web Audio 即時合成（木塊模態合成的落子聲、依欄位的聲像、程序產生的殘響、Karplus–Strong 撥弦的五聲音階終局樂句），不需音檔、離線可用

## 快速開始

線上版：<https://jacoblincool.github.io/banqi/>（推到 `main` 後由 GitHub Actions 自動建置並部署到 GitHub Pages）。網站是 PWA，可以「加入主畫面」安裝成 App，開過一次之後即可離線遊玩；手機請橫放，棋盤會依畫面高度放大。


需要 Rust（含 `wasm32-unknown-unknown` target）、[wasm-pack](https://rustwasm.github.io/wasm-pack/) 與 Node.js。

```sh
./build.sh        # 建置 WASM 並打包網頁
```

輸出 `web/dist/index.html` 是單一檔案（JS、CSS、Worker、WASM 與 Lightning 權重全部內嵌），直接用瀏覽器開啟即可對弈。網頁支援「人機對弈」與「電腦對戰」兩種模式；人機模式預設 Light，電腦對戰預設 A 為 Light、B 為 Lightning。雙方各用獨立的大腦（置換表與亂數），可分別選擇版本與思考時間、暫停、連續對局並累計戰績。版本選擇會保存在瀏覽器；切換版本會開新局並重設戰績，分享回放會記錄當局版本。開發時先跑一次 `./build.sh` 產生 WASM，之後 `cd web && npm run dev`。

Lightning 內嵌的模型與研究基準完全相同，來源與 SHA-256 見 [`engine/models/`](engine/models/README.md)。它是結構化學習評估器；1,057 參數的殘差神經網路仍只用於實驗。網頁的兩個版本都保留既有 MoE 決策與變化度設定；下方研究擂台使用直接搜尋，其得分率不能直接視為網頁模式的勝率。

回放連結以標頭原先未使用的兩個位元記錄雙方模型，連結長度不變。建置 WASM 後，可用 `cd web && npm test` 核對模型檔、WASM 對弈與回放編碼；Rust 介面測試使用 `cargo test --features wasm`。

## 規則

採用台灣 / TCGA 電腦暗棋規則：

- 所有棋子（含俥、傌）每步只能上下左右走一格。
- 帥 > 仕 > 相 > 俥 > 傌 > 炮 > 兵，大吃小、同級互吃；帥不能吃兵，兵可以吃帥；兵不能吃炮。
- 炮必須隔一個棋子（炮架，可為蓋牌）跳吃，距離不限、可吃任何兵種，不能相鄰吃子。
- 蓋著的棋子不能被吃。第一個翻子的人取得翻出棋子的顏色。
- 被吃光或無子可動判負；雙方合計連續 60 步沒有翻子或吃子判和；同一局面出現三次判和。

## 引擎

### 搜尋

- 翻子是機會節點：依剩餘蓋牌中各兵種的數量取期望值，以 Star1 剪枝縮小每個結果的搜尋視窗。
- 走子節點：PVS、Zobrist 置換表（雜湊包含蓋牌池）、killer / history 排序、LMR、空著剪枝（僅在仍有蓋牌時使用，因為翻子幾乎總能當等著）、只搜吃子的靜態搜尋。
- 翻子只在剩餘深度夠深的節點展開（門檻隨思考時間 5–7），非根節點只搜啟發分數最高的幾個翻子點。這是讓中局深度從 5 層提升到 8–9 層的關鍵。
- 重複局面與無進展規則在搜尋中直接判和。

### 評估

- 子力參考 Observer（NTNU）的天敵數模型：每顆子的價值為 `top × ratio^n`，`n` 是還活著（含未翻開）且能吃掉它的敵方非炮棋子數。敵方天敵被吃掉時，己方棋子自動升值，所以引擎懂得用帥換仕這類暗棋特有的交換。帥的價值依敵兵數量遞減，炮獨立計價。
- 位置項：機動性、保護、被困（無安全逃生格）、追殺距離、殘局一對一追殺的奇偶性、炮線、翻子位置風險，以及接近無進展上限時把評估值縮向 0，逼優勢方進取。

### 殘局資料庫

全翻開且總子數 ≤ 4 時，以逆推分析即時算出該子力組合的完美解（原生約 0.2 秒）；剩 5 子且思考時間足夠時，預先建好吃掉任一子後的 4 子表。表中記錄的是距離下一次吃子的步數，因此能正確判斷「贏得了但來不及在 60 步內吃到子」的局面。

### Mixture of Experts

gating 函數依未翻子數、子力差與剩餘棋子數決定各專家的權重：

| 專家 | 作用 |
| --- | --- |
| 一般 / 殘局評估專家 | 兩組各自調參的評估參數，隨未翻子數從 8 到 0 平滑交接 |
| 開局翻子 | 翻子位置風險：翻己方仕、相旁較安全，敵兵未翻完時避開己方帥旁 |
| 戰術搜尋 | Expectiminimax 主搜尋，所有決策的骨幹 |
| 殘局獵手 | 全翻開後偏好縮短與獵物的距離、避免重複 |
| 守勢 / 攻勢 | 落後時製造變數、保住和棋；領先時吃子施壓、避免重複 |
| 殘局資料庫 | ≤ 4 子時接手，給出完美解 |

最後在搜尋分數接近最佳的候選著法中，依專家偏好加權後抽樣。抽樣溫度同樣由 gating 決定：開局隨機性高，戰術與殘局的關鍵局面收斂到最佳著。網頁上會顯示每一步各專家的權重。

## 調參與實驗結果

網路上找不到公開的暗棋棋譜，所以參數全部來自自我對弈：非同步 SPSA，每回合以 θ+cΔ 與 θ−cΔ 下一對（同一牌局、交換先手）的棋局，依勝負更新參數。每項改動都以獨立的擂台對局驗證：

| 改動 | 對上一版 |
| --- | --- |
| 線性子力 → 天敵數子力 | +237 Elo |
| SPSA 第 1 輪 | +148 Elo |
| SPSA 第 2 輪（加入殘局專家參數） | +119 Elo |
| 翻子深度門檻 | +53 Elo |
| SPSA 第 3 輪 | +52 Elo（100ms/步複驗 +58） |
| 迭代加深用滿 65% 時間預算 | +32 Elo |
| SPSA 第 4 輪（兵種加成、蓋牌折價） | +33 Elo |
| SPSA 第 5 輪（60ms/步） | −5 ± 22 Elo，已收斂，採用第 4 輪參數 |

除特別註明外，每項 400–800 盤、每步 25ms。這些是自我對弈的相對 Elo，數字會偏高。MoE 的多變模式對確定性版本為 −1 Elo（誤差內）。對上同一評估但只搜 2 層的版本勝率約 82%，其餘輸局多半來自翻子運氣。

各輪參數在 `tuning/round*.txt`，24 盤自我對弈棋譜（每步 1 秒，含評分與搜尋深度）在 `games/`。

### 與公開引擎對弈

以 `match` 工具對上能公開取得的暗棋引擎，每條件 400 盤（200 副牌、交換先後手），終局依本專案規則判定，無任何錯誤局：

| 對手 | 條件 | 我方 勝／和／負 | 得分率 | Elo（95% 區間） |
| --- | --- | --- | --- | --- |
| [MistyBanqi](https://github.com/brianhliou/misty-banqi) 0.2.5 | 我方 1 秒/步，對手 350 萬節點/步（mistboard.com 正式強度） | 262／86／52 | 76.2% | +203（+171 ～ +238） |
| MistyBanqi 0.2.5 | 雙方 300ms/步 | 262／78／60 | 75.2% | +193（+161 ～ +229） |
| [George0828Zhang hw3](https://github.com/George0828Zhang/chinese-dark-chess-hw)（NTU TCG 2021 第 2 名） | 雙方 300ms/步 | 319／74／7 | 89.0% | +363（+327 ～ +407） |

先後手的勝負分布相近，時限拉長後差距也沒有縮小。和局多為 60 步無進展（佔優卻收不完殘局），是主要的改進空間。CLAP_CDC、Yahari 等比賽冠軍程式沒有公開，無法比較。

## 開發工具

在 `engine/` 下：

```sh
cargo test                                                         # 規則與殘局庫測試
cargo run --release --bin arena   -- 400 25 "A 設定" "B 設定" 16    # 自我對弈擂台
cargo run --release --bin spsa    -- 10000 20 14                   # SPSA 調參
cargo run --release --bin bench   -- 2000                          # 各階段搜尋深度
MISTY_BIN=… cargo run --release --bin match -- misty 400 300 6     # 與外部引擎對弈（見下）
cargo run --release --bin records -- 24 1000 ../games 4            # 產生棋譜
python3 apply_params.py "$(cat ../tuning/round4.txt)"              # 把調參結果寫回預設值
```

`match` 與外部引擎對弈，同一副牌交換先後手，終局一律依本專案規則判定：`misty`（[MistyBanqi](https://github.com/brianhliou/misty-banqi)，UCI，需把 `engine.rs` 的 40 步和棋改為 60；`misty:nodes=N` 改用固定節點數）或 `george`（[George0828Zhang hw3](https://github.com/George0828Zhang/chinese-dark-chess-hw)，TCG CDC 協定，需在 `estimatePlyTime` 讀取 `PLY_MS` 環境變數以固定每步時間）。執行檔路徑由 `MISTY_BIN`、`GEORGE_BIN` 指定，`REC=目錄` 可存下每盤棋譜。

`arena` 的設定字串格式為 `key=value,...`，可覆寫任何評估參數（見 `src/eval.rs` 的 `PARAM_NAMES`，殘局專家參數加 `e.` 前綴）或搜尋設定，例如 `fmd`、`iflips`、`nmp`、`contempt`、`variety`、`tmul`。

## 輕量學習評估器

新增可選的 64 → 16 → 1 殘差網路（1,057 個參數、4,236 bytes），可使用現有搜尋與殘局庫。 在事先固定、未參與訓練或選模的 800 盤對局中，雙方每步 25ms，學習評估器取得 312 勝／236 和／252 負，得分率 53.75%（以牌局配對 bootstrap 的 95% 區間為 51.13%–56.38%，約 +26 Elo）。此結果僅驗證這個時間條件。訓練流程、模型、成對對局評測與結果見 [`training/`](training/README.md)。預設引擎的評估器不變；以 `arena` 的 `model=路徑,model_scale=倍率` 載入實驗模型。

另有受 handwired 方法啟發的[結構化可訓練評估器實驗](training/structured/README.md)：初始權重逐分重現原評估，加入棋種參數與交互項後以梯度訓練。模型檔為 1,360 bytes，使用 `structured=路徑` 載入。第一輪各 800 局的獨立測試，對原引擎得分率 47.56%，對上述殘差模型為 44.31%，尚未帶來棋力提升；原型、等價驗證與完整結果均保留供後續研究。

[第二輪](training/ranking/README.md) 改用較強教師並加速推論，選出的分數回歸模型在每步 25ms、800 局獨立測試中，對原引擎取得 **53.50%** 得分率（95% 區間 50.94%–56.06%，約 +24 Elo）；對先前殘差模型為 **50.81%**（48.25%–53.38%），尚無超越或等效的統計證據。模型檔仍為 1,360 bytes；本機微基準下單次評估比先前殘差模型少約 39% 時間。以 `structured=training/ranking/value.cse` 載入。排序訓練也已測試，但未勝出選模；預設引擎仍不變。

[Scaling 實驗](training/scaling/README.md) 與[資料量 × 容量補測](training/scaling-joint/README.md) 共完成 9 個條件、27 次訓練及 6,040 局測試，包含 512／2,048 局資料、139／499／1,948 個可訓練參數、局面覆蓋、更新範圍及 160／640ms 教師搜尋。更多資料與容量降低了教師評分的驗證誤差，但尚未建立棋力提升的證據。凍結候選對原引擎為 53.56%，對第二輪模型為 49.88%（95% 區間 47.38%–52.31%）；因此保留先前模型的推薦。新增的查表擴充可用 `expanded=路徑` 載入，`nodes=8192,fmd=5` 可進行固定節點預算的比較。

[容量 × test-time 搜尋實驗](training/test-time/README.md) 另完成 **2,592 局**，交叉比較三種容量與每步 10／40／160ms，並加入固定節點控制。對同一個固定 40ms 的對手，三種容量從 10ms 增至 160ms 分別提升約 140／145／109 Elo；搜尋收益明確，但尚無證據顯示參數越多，收益越大。大模型對小模型的直接對戰得分增益為 +6.77 個百分點（95% 區間 −1.04～+14.58）。本輪固定翻棋搜尋門檻並關閉殘局庫；結果僅適用於此控制設定，三個時間點不足以推斷棋力上限。見[完整曲線](training/test-time/test-time-scaling.png)。

[499 參數模型的後續訓練實驗](training/improve499/README.md) 固定模型容量，比較較深教師、更新幅度與走法排序等六種方案，共完成 **18 次訓練、2,752 局對戰**。選出的候選在獨立測試中，對凍結的 499 基準於 40ms 得分率為 **49.75%**（95% 區間 47.67%–51.75%，1,200 局），於 160ms 為 **48.50%**（44.88%–52.12%，400 局）。兩者都未證實提升；降低教師評分誤差沒有穩定轉化為棋力，因此後續仍沿用原 499 基準。模型、訓練與對戰紀錄、驗證結果和[圖表](training/improve499/results.png)均保留。

[五版本 × 四種時間的比較](training/tournament1600/README.md) 完成 **1,792 局**，包含新增的 480 局 1,600ms 測試：原版、139／499／1,948 參數結構化版與 1,057 參數神經網路版，在每步 **25／100／400／1,600ms** 循環對戰，並與固定 25ms 原版比較。循環賽點估計第一依序為 499（53.9%）、1,948（57.0%）、139（53.5%）、499（54.7%）；每個版本每個時間點共 128 局。1,600ms 的 499 對 139 為 **15 勝／13 和／4 負，得分率 67.2%**（95% 區間 56.2%–78.1%），相較 400ms 的平手，是值得新牌確認的訊號；但對同時間原版為 56.2%（42.2%–70.3%），尚未確認全面最強。

對固定 25ms 原版，499 在 400 與 1,600ms 的得分率皆為 75.0%，配對增益區間為 −15.6～+15.6 個百分點，不能判定已達上限。模型間 400→1,600ms 與 25→1,600ms 的收益差區間都包含零，較大容量的額外搜尋收益仍未確認；繼續保留 499 作為研究基準。這是每組 16 副牌、未校正多重比較的探索實驗；1,600ms 也跨過原有翻子深度與殘局表預建門檻。見[比較圖](training/tournament1600/comparison.png)、[對戰矩陣](training/tournament1600/head-to-head.png)與[完整核對紀錄](training/tournament1600/verification.json)。
